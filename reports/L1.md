# L1 单步学习报告

> 日期：2026-11-17 ｜ 阶段：L1 带墙单步 ｜ 模型：Qwen3-0.6B + LoRA
> 数据：balanced L1 + natural L1 ｜ 训练：20 updates ｜ 评估：greedy

---

## 0. 重要数据修复

最初的 L1 数据生成器只生成了竖墙：

```python
_SHAPES = {
    "L1": (_vertical_wall,),
    ...
}
```

统计确认：

```text
旧 train L1: 600/600 竖墙，0 横墙
旧 val   L1:  80/80  竖墙，0 横墙
旧 test  L1:  80/80  竖墙，0 横墙
```

这不是随机种子问题，而是墙方向被硬编码了。竖墙只影响左右移动，
导致 L1 实际上只是 **vertical-only L1**。

已修复：

- 新增 `_horizontal_wall()`；
- 改为：

```python
"L1": (_vertical_wall, _horizontal_wall)
```

- 增加测试，要求 L1 同时覆盖竖墙和横墙；
- 重新生成 `data/maps`、`data/eval_states.jsonl`、`data/states`；
- 确认 L0/L2/L3/L4 地图未变化，只有 L1 变化；
- `check_dataset.py`、`check_states.py`、全量测试全部通过。

修复后的 L1 地图：

```text
train: 竖墙 301 / 横墙 299
val:   竖墙 43  / 横墙 37
test:  竖墙 41  / 横墙 39
```

> 本报告以下结果全部来自修复后的数据。
> 旧的全竖墙 L1 结果不再作为最终结论，只保留为历史调试记录。

## 1. 阶段目标

L1 在 L0 的基础上加入单面墙，仍然只做**单步方向接地**：

- 给定当前状态（含墙）；
- 选一个让 BFS 距离减 1 的动作；
- 不做多步，不做完整路径规划。

L1 主要新增难点：

- 墙的朝向、位置和门需要被模型理解；
- 竖墙阻挡左右移动，横墙阻挡上下移动；
- 某些方向会被墙挡住；
- 斜对角 mixed 状态之外，单方向状态更多。

## 2. 数据与评测

### balanced L1

| split | 总数 | singleton | mixed |
|---|---:|---|---|
| train | 320 | 每个方向 64 | 每个组合 16 |
| val | 64 | 每个方向 12 | 每个组合 4 |
| test | 64 | 每个方向 12 | 每个组合 4 |

### natural L1

`data/eval_states.jsonl` 中 60 条 L1 状态。

评测沿用实验协议：

- greedy；
- val 用于 best/早停；
- test 只做最终报告；
- natural 作为辅助对照；
- 主指标：balanced test optimal；
- 方向指标：singleton accuracy。

## 3. 训练配置

```text
base: Qwen3-0.6B
adapter: LoRA r=16
lr: 5e-5
states/update: 16
G: 8
temperature: 1.2
max_tokens: 40
updates: 20
eval_every: 5
seed: 7
```

两组都跑满 20 updates，不早停，保证可比。

## 4. 观测对照

| 组 | 观测 |
|---|---|
| A | `minimal` 绝对坐标 |
| B | `rel + few-shot`（`rel_l1`，一竖一横两条带墙示例） |

L1 的 `rel_l1` few-shot 在 L0 的四条 cardinal 示例之外，增加：

- 一条带竖墙的 down 示例；
- 一条带横墙的 up 示例。

平均 prompt 长度约 823 tokens。

---

## 5. 修复后的结果

| 指标 | A absolute | B rel + few-shot |
|---|---:|---:|
| balanced test baseline | 46.88% | 51.56% |
| balanced test best | 46.88% | **79.69%** |
| natural test best | 75.00% | **90.00%** |
| valid | 100% | 100% |
| best val optimal | 46.88% | **67.19%** |
| final degenerate | 93.75% | **100%** |

### A absolute

- baseline：val 46.88% / test 46.88% / natural 75.00%；
- update 5 后退化成只输出 `up`；
- update 20：val 31.25% / test 31.25% / natural 45.00%；
- 最终 test 方向 singleton：

```text
up    100%
down  0%
left  0%
right 0%
```

训练不是“学不会”，而是**塌缩到单一动作**。加入横墙后，absolute
观测无法同时处理左右和上下被墙阻挡的情况。

### B relative + few-shot

- baseline：val 50.00% / test 51.56% / natural 71.67%；
- update 10：test 79.69% / natural 90.00%；
- update 20：val 67.19% / test 79.69% / natural 90.00%；
- 最终 test 方向 singleton：

```text
up    66.7%
down  50.0%
left  91.7%
right 83.3%
```

最终 test 动作分布：

```text
left 27 / right 15 / down 9 / up 13
```

relative + few-shot 没有塌缩成单一方向，能够同时处理竖墙和横墙。
但 `down` 仍然只有 50%，`up` 约 67%，训练集和 eval 仍有明显 gap：

```text
最后训练 singleton: up 66.7% / down 100% / left 100% / right 100%
balanced test:      up 66.7% / down 50%  / left 91.7% / right 83.3%
```

B 最后 degenerate 100%，训练组基本饱和，继续跑同样的 20 updates
不会自然解决 up/down。

---

## 6. 是否达到 L1 完成标准

协议中 L1 建议标准：

```text
balanced test optimal >= 80%
natural test optimal >= 80%
四个 singleton >= 75%
valid >= 99%
```

对照：

- A：test 46.88%，最终完全塌缩，不达标；
- B：natural 90%、valid 100%，但 test 79.69%、up 66.7%、down 50%，不达标；
- B 距离 test 80% 只差一个样本（64 条中 51 条正确，80% 需要 52 条）；
- 两组都出现高退化，L1 还没有完成。

结论：

> relative + few-shot 是明显更好的 L1 观测，但 L1 还没有完全解决。
> 当前主要缺口是 **up 和 down 单方向状态**，不是格式，也不是训练链路。
> 数据方向修复后，absolute 的失败更加明显，不能再把旧竖墙结果当作 L1 结论。

---

## 7. 关键发现

1. **原 L1 数据存在方向覆盖 bug**
   - 只有竖墙；
   - 竖墙只影响左右，横墙只影响上下；
   - 修复后 train/test 都接近 50/50。

2. **横墙让 absolute 观测直接失效**
   - 修复前 absolute best test 约 65.62%；
   - 修复后 absolute 训练到 update 5 就塌缩成只输出 up；
   - 最终 test 31.25%。

3. **relative + few-shot 仍然明显更好**
   - test 79.69% vs 31.25%；
   - natural 90.00% vs 45.00%；
   - 能同时覆盖竖墙和横墙。

4. **up/down 是当前瓶颈**
   - 最终 up 66.7%、down 50%；
   - 训练集已经接近饱和，但 eval 的 down 仍然只有 50%；
   - 说明数据覆盖、难例或采样仍需针对性改进。

5. **L1 在 20 updates 后已经饱和**
   - degenerate 到 100%；
   - 最后几条 update 的 `samples` 多为 0；
   - 再跑更多 update 收益很低。

## 9. 局限

- balanced test 64 条，单 seed；
- per-direction 只有 12 条 singleton；
- 没有 OOD；
- 没有 SFT；
- 相对 few-shot prompt 约 823 tokens，成本高于 absolute；
- 训练采样仍是状态串行、组内 G 并行。

---

## 10. 下一步

不建议直接进入 L2。L1 还差 up/down，建议先做 L1.5：

1. 针对 up/down 单方向状态做**类别均衡采样**；
2. 增加 up/down 的墙示例，分别覆盖竖墙和横墙；
3. 检查横墙/竖墙与 up/down 的交互，确认 down 的 50% 是数据问题还是模型偏置；
4. 如果仍然学不会，再考虑 SFT 冷启动；
5. 等 L1 达到 test ≥80%、四方向 ≥75% 后再进入 L2。
